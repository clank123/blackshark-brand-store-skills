# BlackShark Project Handoff

Prepare the smallest handoff that lets responsible people execute, coordinate, report, and make the next decision. This general core is organization- and platform-neutral.

## Preserve the decision boundary

Inherit the supplied objective, decisions, owner, authority, constraints, and non-goals. Do not reapprove（不重新审批）an agreed direction. Ask for a human decision only when the handoff introduces a materially new commitment, owner, risk, external release, or choice outside current authority. A missing execution detail blocks only the task that depends on it; it does not send unaffected work back through approval.

## Choose a proportional shape

Use a lightweight handoff（轻量交接）for an approved simple task with one clear owner, low risk, reversible execution, and no independent gate. Keep it on the current document, task, or conversation when that carrier is usable.

Use a coordinated handoff when several owners or dependencies need a shared interface but remain under one decision boundary. It may add a cross-project dependency view while each existing project keeps its own source of truth; that alone does not justify repackaging them.

Use a complex project（复杂项目）package only when work has material resource commitments, sustained coordination, separate gates, multiple result decisions, or a real need for one durable source of truth that existing carriers cannot provide. Project packaging is a coordination response, not a status symbol.

## Shared interface

Include only what the work needs from this interface:

- action and intended outcome;
- responsible owner, collaborators, and decision boundary;
- deliverable or observable completion;
- deadline or operating window;
- dependencies, conflicts, and protected operations;
- acceptance evidence and reporting route;
- stop, rollback, escalation, and next-decision conditions.

Preserve explicit unknowns. Do not invent owners, dates, links, evidence, or approvals. Separate readiness from business effect: a handoff can be ready to run without proving that the method or commercial result works.

## Output

Return the selected shape, the executable handoff, remaining blocked items with their exact impact, and the next decision point. When the task asks for a deliverable, finish the usable handoff within current authority rather than stopping at a list of missing fields.

Read `references/handoff-shapes.md` for proportional examples and readiness checks.
