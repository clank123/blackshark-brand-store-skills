# Handoff shapes

## Lightweight handoff

Use a sentence or compact task note when one owner can execute without a new decision:

`Action | owner | deliverable | due/window | acceptance | report/exception route`

Add a dependency or stop condition only when it changes execution.

## Coordinated handoff

Provide a short responsibility and sequence view:

- inherited decision and current boundary;
- complete actions and owners;
- predecessor and shared-resource dependencies;
- deliverables and timing;
- acceptance evidence;
- unresolved execution details and their local impact;
- exception owner and next decision point.

This view may coordinate several existing projects without replacing their own records. Escalate to a new project package only when those carriers cannot preserve a necessary shared contract, gate, or result decision.

## Project package

A complex package may contain a direction/contract source, a progress view, and a coordination card. The exact tools and fields belong to the implementation context. Keep the shared concepts traceable across the package, but do not add fields that serve no current execution or decision need.

## Readiness check

Say `ready` only when the next action has an owner, usable input, timing, acceptance, and protection or escalation needed for its risk. Say `partly ready` when unaffected work can proceed and identify the exact blocked action. Never use a completeness check as proof of business effect.
